# V1.0.1 - Vendure 3.6.5 -> 3.7.3 Upgrade Impact Assessment

Baseline: main @ 938947c, Vendure 3.6.5. Target: 3.7.3 (2026-09-01).
Verdict: NO UNRESOLVED BLOCKER. Proceed V1.0.2 -> V1.0.9.
Rule: no speculative migration; schema via Vendure CLI on upgrade branch.
Changelog source: master CHANGELOG.md sections 3.7.0/3.7.1/3.7.2/3.7.3.
Vendure states 3.7.3 has no breaking API changes, but tightens behaviour.

## 1. Package alignment (package.json + lockfile verified)

All 8 direct @vendure/* pins are 3.6.5: core, asset-server-plugin,
dashboard, email-plugin, graphiql-plugin, job-queue-plugin, cli,
testing. Target for all 8: 3.7.3. @vendure/common is transitive and
moves with core. Upgrade = single bump of all 8 (V1.0.3) + reconcile.

  superadmin/superadmin. Action: non-default SUPERADMIN_USERNAME and

  AuthenticationStrategy. No custom strategy in src. No impact; noted

- Coupons case-insensitive; CouponRemovedDuringCheckoutError added to
  AddPaymentToOrderResult; usage-limit and race fixes. No coupon use in

  after codegen (V1.0.5).
- CustomerChannelAssignmentStrategy / OrderLineDiscountDistribution
  Strategy not configured; defaults apply. No impact.
- Email plugin mjml v4->v5, nodemailer v6->v9. Templates are .hbs via
  ChannelBasedTemplateLoader; no custom transport. Low: eyeball mail.
- @nestjs/terminus no longer transitive. No import in repo. No impact.
- Province export, DataLoader batching, codegen tweaks: expect codegen
  diffs in V1.0.5 only.

## 4. 3.7.3 impact (security baseline)

- registerCustomerAccount: password no longer stored when a User
  already exists for the email via another strategy and has no
  password; verification token emailed instead; verifyCustomerAccount
  sets it; name/phone/custom fields ignored when User exists. Saa9vi
  specs use fresh emails; tenant admin flow is Administrator-based.
  Expect green; add duplicate-email-across-strategy probe.
- administrators/administrator scoped to roles the caller has authority
  over. Saa9vi already overrides administrators (INV-016) and roles
  with the same shape. Core now enforces underneath; keep the override
  (singular role query BUG-026 has no stated core equivalent).
- updateChannel/deleteChannel scoped to caller channels. Saa9vi never
  calls these as tenant admin (registration uses ChannelService under
  superadmin ctx). No breakage; probe tenant-admin denial.
- duplicateEntity, assign/remove-to-channel, createProductOption, and
  Order payment/refund/fulfillment/customer-note ops now throw when
  the target is not visible in the active channel. THE tenant boundary
  fix: Tenant B admin on Tenant A IDs must fail. CMS services call
  ChannelService.assignToChannels/removeFromChannels with
  SuperAdmin-gated remove and explicit channelIds; confirm no
  cross-channel flow as non-privileged caller. Permanent suite (sec 9).
- Job data over Admin API no longer includes session token. After
  upgrade: purge settled job data, consider invalidating admin
  sessions. RequestContext.session type change deferred to next minor.
  No reliance on session token in job data found in Saa9vi queues.
- apiOptions.csrfPrevention new, defaults false. Nothing changes unless
  enabled. Decision recorded in sec 5.
- Asset server: nosniff + CSP on every asset; SVG/HTML/XML served with
  Content-Disposition attachment (URL downloads; img-embed unaffected).
  No permittedFileTypes config; no SVG-serving dependency found.
  Verify images + PDF inline in V1.0.8.
- file-type v21 renames 4 MIMEs (x-flac, x-matroska, x-apache-arrow,
  x-parquet to IANA names). Saa9vi lists no explicit old values;
  default wildcard config unaffected. No impact.

## 5. CORS/CSRF decision (record now, harden in V1.2)

- Current: apiOptions.cors reflects any origin with credentials:true.
  Vendure 3.7.3 logs a startup warning for exactly this; Saa9vi flags
  it in production-readiness.md.
- DECISION: V1.0 keeps csrfPrevention:false (new default) and current
  CORS so the upgrade diff stays behaviour-neutral. V1.2 owns explicit
  origin allowlist + csrfPrevention:true with client rollout
  (Apollo-Require-Preflight for GET queries/uploads). GET-client
  inventory is a V1.2 prerequisite. Expected startup warning is the
  V1.2 trigger; do not silence it.
- **SUPERSEDED 2026-09-27 (V1.0.9):** `csrfPrevention: true` is now set
  in `src/vendure-config.ts`. The GET/upload client inventory this
  decision required was done first: the storefront
  (`nextjs-starter-vendure/src/lib/vendure/api.ts`) sends every GraphQL
  request as POST + `Content-Type: application/json` with no GET queries
  and no multipart uploads to the GraphQL APIs, and `@vendure/dashboard`
  / `@vendure/testing` send `Apollo-Require-Preflight` natively — so
  `application/json` traffic (all of it) is unaffected. The CORS
  origin-allowlist half of this decision is still open and remains V1.2.
  See `v1.0.9-vendure-373-validation.md`.

## 9. Mandatory post-upgrade regression matrix (V1.0.7 + V1.0.8)

A. Permanent cross-channel financial boundary suite (new, never
   remove): Tenant A order/payment/refund; Tenant B admin attempts on
   A IDs MUST FAIL: addManualPaymentToOrder, transitionPayment /
   settlePayment, createRefund/settleRefund, transitionFulfillment,
   addNoteToOrder, addNoteToCustomer. Payment case is critical.

   remove-from-channel, duplicateEntity, administrators/administrator
   reads, updateChannel/deleteChannel, createProductOption,
   adjustDraftOrderLine, Asset/StockLocation update, Promotion /
   FacetValue delete, updateAdministrator password path.
C. Existing suites: tenant-plugin (75), bbb-channel-isolation, R4
   lifecycle, marketplace/commission/reconciliation, subscription
   self-serve + webhooks, customer-deletion, persona-b + admin-api
   smoke, dashboard contract.
D. Perimeter/asset eyeball: CORS warning present, asset headers/CSP,
   SVG download, PDF inline, email renders.
